# Контракт коннектора

Что агенту нужно от сервиса рассылок. Написано в возможностях, а не в именах инструментов: RuSender —
эталонная реализация, но не единственная возможная.

Если вы переносите агента на свой ESP с MCP — пройдите по таблице и заполните колонку «у вас».
Незакрытая возможность не ломает агента целиком: он теряет конкретную проверку или отчёт и должен
сказать об этом вслух, а не тихо пропустить.

## Обязательное

Без этого агент бесполезен.

| # | Возможность | Зачем | RuSender | У вас |
|---|---|---|---|---|
| 1 | Список кампаний с метриками | История проекта, пересечения, подбор From Name | `public_campaigns_list(withStats)` | |
| 2 | Кампания по id с метриками | Preflight и разбор результата | `public_campaigns_get_by_id(withStats)` | |
| 3 | Список аудиторий и их размеры | Охват, опознание проекта | `public_lists_list`, `public_lists_statistics` | |
| 4 | Шаблон письма с HTML | Проверка ссылок, UTM, отписки, переменных | `public_templates_get_by_id` | |
| 5 | Поля аудитории (переменные) | Сверка `{{переменных}}` письма с базой | `public_variables_list(listId)` | |
| 6 | Отправители и их подтверждение | Кампания не стартует с неподтверждённого адреса | `public_senders_list` | |

## Важное

Без этого агент работает, но заметно слабее.

| # | Возможность | Зачем | RuSender | У вас |
|---|---|---|---|---|
| 7 | Домены и статус верификации | Без верификации письма режет DMARC | `public_domains_list` → `isVerified` | |
| 8 | Создать и обновить черновик | Сборка рассылки | `public_campaigns_create/update` | |
| 9 | Разрезы метрик: по дням, провайдерам, ссылкам | Разбор результата | `get_activity`, `get_stats_by_domains`, `get_link_clicks` | |
| 10 | Сегменты: перечислить и создать по условиям | Сужение аудитории | `public_segments_list/create` | |
| 11 | **Исключение «не получал кампанию X»** | Частотный лимит, email fatigue | условие `activeInCampaign` + `notParticipated` | |
| 12 | Охват с учётом сегмента | Строка `Excluded` в карточке | `chunks_preview` с большим `initialChunkSize` | |

Пункт 11 — самый редкий. Нет его — проверка пересечений превращается в предупреждение без действия:
агент покажет, что аудитория уже получала письмо, но исключить не сможет. Так и скажи человеку.

## Необязательное

| # | Возможность | Зачем | RuSender |
|---|---|---|---|
| 13 | Метки UTM на уровне кампании | Сервис проставляет метки сам | объект `utm` в кампании |
| 14 | Папки кампаний | Группировка по проектам | `public_folders_list` |
| 15 | Транзакционные ключи и их статистика | Дашборд по ключу | `public_external_mail_*` |

## Запуск

Отдельно, потому что это единственное необратимое действие.

| Возможность | RuSender |
|---|---|
| Запустить кампанию | `public_campaigns_schedule` |
| Остановить запущенную | **нет** |

**Требование к любому адаптеру: запуск вызывается только после явного подтверждения человеком.**
У RuSender нет ни паузы, ни отмены — остановить рассылку из чата невозможно. Если у вашего ESP
отмена есть, подтверждение всё равно остаётся: часть базы получит письмо раньше, чем человек успеет
среагировать.

## Различия, на которые стоит смотреть в первую очередь

Эти вещи у разных сервисов устроены по-разному и ломаются тихо:

- **База для процентов.** У RuSender `click.rate` считается от открытий, то есть это CTOR, а не CTR.
  Перепутать — отчитаться о рассылке в несколько раз лучше, чем она отработала. Считайте метрики
  сами из абсолютных чисел, а готовые проценты используйте только для сверки.
- **Ссылка отписки.** У RuSender это `{{unsubscribe_url}}`, строго в нижнем регистре и внутри
  `<body>`. Синтаксис и регистр у других сервисов свои.
- **Синтаксис переменных.** `{{name}}`, `%NAME%`, `*|NAME|*` — проверку переменных надо настроить
  под свой синтаксис, иначе она не найдёт ничего и промолчит.
- **Пагинация и лимиты.** Где-то 100 записей на страницу, где-то 1000. Влияет на то, какие отчёты
  реально собрать, а какие обойдутся в сотни вызовов.

## Как это устроено внутри навыков

Наши три навыка (`rusender-agent`, `rusender-preflight`, `rusender-results`) обращаются к коннектору
в паре десятков мест. Имена инструментов вынесены в раздел «Инструменты» каждого SKILL.md — менять
надо там, а не по всему тексту.

Десять отчётных навыков из upstream написаны под RuSender API целиком и на другой сервис не
переносятся. Это нормально: они про конкретный сервис, а не про метод работы.
