# Расписание: как включить автообновление

Агент сам не просыпается. Чтобы он возвращался за дозревшей статистикой без напоминаний, нужен
планировщик.

В комплекте лежит готовая задача — `routines/daily-refresh.md`, будние дни в 10:00. **По умолчанию
она выключена.** Это осознанно: задача ходит в ваш аккаунт и пишет в файлы, и включать такое за вас
неправильно.

## Claude Code

Скажите в сессии:

```
Настрой задачу по расписанию: каждый будний день в 10:00 выполнять routines/daily-refresh.md
```

Либо командой `/schedule`, если она доступна в вашей сборке. Проверить и выключить — там же.

## Через cron

Если планировщик Claude Code недоступен, подойдёт обычный cron. Пример для будних дней в 10:00:

```
0 10 * * 1-5 cd /путь/к/email-agent && claude -p "$(cat routines/daily-refresh.md)" >> logs/refresh.log 2>&1
```

Папку `logs/` создайте сами, она в `.gitignore`.

## Как проверить, что работает

Через сутки после включения посмотрите `log.md` любого проекта, по которому были отправки: там
должна появиться строка вида «обновлено кампаний: N». Если её нет — задача не отработала.

Второй признак: в `history.jsonl` у свежих кампаний `as_of` должен подтягиваться к сегодняшней дате,
оставаясь позже `sent_at`.

## Чего не стоит ставить в расписание

- **Создание и отправку рассылок.** Никогда. Человек должен быть за клавиатурой в момент, когда
  письмо уходит.
- **Сборку дашбордов.** Они нужны по запросу; ежедневный артефакт никто не читает.
- **Частоту чаще раза в день.** Статистика не меняется поминутно, а лимиты API расходуются.
