# Получение данных RuSender

Используй фактически доступные инструменты подключённого RuSender. Имена ниже соответствуют текущему MCP-коннектору; если схема инструмента изменилась, следуй его актуальному описанию.

## Нужные операции

- `rusender_public_external_mail_keys_list` — список ключей, если `key_id` не указан.
- `rusender_public_external_mail_keys_get_by_id` — имя, статус и домен выбранного ключа.
- `rusender_public_external_mail_key_stats` — независимая агрегированная статистика ключа. Передай `keyId`, `dateFrom`, `dateTo`; без дат коннектор возвращает последние 30 дней.
- `rusender_public_external_mails_list` — последние транзакционные письма. Передай `keyId`, `limit`, `page`; ответ отсортирован от новых к старым и возвращает `hasMore`.

## Пагинация

1. Начни с `page=1` и максимально разумного `limit`, разрешённого схемой.
2. Добавляй страницы по порядку, пока не собрано N записей либо `hasMore=false`.
3. Обрежь результат до ровно N самых новых писем.
4. Не запрашивай следующую страницу после достижения N.

## Минимальный безопасный набор данных

До записи на диск преобразуй каждое письмо к форме:

```json
{
  "id": 123,
  "createdAt": "2026-08-28T12:20:11Z",
  "status": "opened",
  "subject": "Тема письма"
}
```

Не сохраняй `toEmail`, `fromEmail`, имена, тело, HTML, текст, заголовки, параметры шаблона и SMTP-ответы. Если для отдельного графика нужен SMTP-класс ошибки, агрегируй его в памяти и сохраняй только обезличенную категорию и количество.

## Ошибки доступа

- Если RuSender не подключён, сообщи, что нужен коннектор, и остановись.
- Если ключ не найден в текущем аккаунте, не подставляй похожий ID из другого аккаунта.
- Если данных меньше N, используй все доступные записи и явно подпиши фактический размер выборки.
