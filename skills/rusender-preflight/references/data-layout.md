# Память агента: формат файлов

Общий контракт для навыков `rusender-agent`, `rusender-preflight` и `rusender-results`. Файл
одинаковый во всех трёх — навыки ставят по отдельности, общей папки у них нет.

**Версия схемы: 1.** Если встретил файл с другой версией — не ломай его молча, скажи человеку.

## Где лежит

Корень памяти — `.rusender-agent/` в текущей рабочей папке. Не в домашней: у человека может быть
несколько аккаунтов RuSender и несколько рабочих папок, и смешивать их нельзя.

```
.rusender-agent/
  ACCOUNT.md                     # снимок аккаунта: домены, отправители, дата сверки
  projects/<slug>/PROFILE.md     # контекст проекта
  projects/<slug>/history.jsonl  # по строке на кампанию
  projects/<slug>/notes.md       # наблюдения и гипотезы
```

`<slug>` — латиница, цифры и дефис. Он же в поле `slug` профиля, он же в `project` строк истории.

Если папки `.rusender-agent/` нет — памяти нет. Это нормальное первое состояние, а не ошибка:
предложи bootstrap и работай без контекста, пока человек не согласится.

## Что в память класть нельзя

Только агрегаты уровня кампании. **Никаких email-адресов, имён, телефонов, значений переменных
контактов, тел писем и SMTP-ответов.** Это та же линия, что проведена в
`rusender-key-dashboard/references/rusender-tools.md`, и она здесь не смягчается: файлы лежат в
рабочей папке, попадают в git и в бэкапы.

Тема письма и имя кампании — можно: это ваш собственный контент, а не данные подписчика.

## PROFILE.md

Фронтматтер для машины, проза под ним для модели. Обязателен только `slug` и `name` — остальное
доращивается по мере того, как человек рассказывает о проекте.

```markdown
---
schema: 1
slug: shop-rosa          # demo: true — если это вымышленный профиль из комплекта
name: "Роза — доставка цветов"
language: ru
sender:
  id: 41
  email: news@rosa.example
  from_name: "Роза"
domain: rosa.example
folder_id: 10
list_pattern: "| Роза"
default_templates: [2317]
utm:
  source: email
  medium: rusender
  campaign_from: name
frequency_cap:
  sends: 2
  days: 7
updated: 2026-09-18
---

## Продукт
...

## Аудитория
...

## Tone of voice
...

## Чего писать нельзя
...

## Типовые сегменты
...
```

### Поля

| Поле | Зачем | Если пусто |
|---|---|---|
| `slug`, `name` | Опознание проекта в задаче | Профиль невалиден |
| `demo` | `true` у вымышленных профилей из комплекта навыка. Запрещает подставлять их id в коннектор | Считай профиль настоящим |
| `language` | Язык писем и отчётов | Считай, что русский |
| `sender.id`, `sender.email` | Подставить отправителя без вопросов | Спроси и предложи из `senders_list` |
| `sender.from_name` | Имя отправителя обязательно для старта | Возьми из истории кампаний по этому адресу |
| `domain` | Проверка верификации | Возьми из части после `@` |
| `folder_id` | Куда класть кампанию, и как отобрать кампании проекта | Отбирай по отправителю |
| `list_pattern` | Подстрока в имени списка, по которой видно проект | Показывай все списки |
| `default_templates` | «Возьми наш стандартный шаблон» | Спроси |
| `utm` | Сверка меток в preflight | Проверку UTM пропусти и скажи об этом |
| `frequency_cap` | Окно для проверки пересечений | Возьми 7 дней по умолчанию, но скажи, что это дефолт |
| `updated` | Когда профиль трогали | — |

**id из профиля — подсказка, а не истина.** Списки пересоздаются, шаблоны удаляются вместе с
кампаниями. Перед использованием проверяй id свежим вызовом коннектора. Если id не нашёлся — не
подставляй похожий, скажи и спроси.

## history.jsonl

Одна строка — один снимок метрик одной кампании. JSON без переносов, кодировка UTF-8.

```json
{"schema":1,"campaign_id":112538,"project":"shop-rosa","name":"18.09.26 Активные | Сентябрьский дайджест","subject":"Собрали три букета недели","sent_at":"2026-09-18T09:00:00Z","as_of":"2026-09-19T08:12:00Z","audience":{"list_ids":[42761],"segment_id":null,"kind":"active","recipients":42731,"excluded":2108},"delivered":42104,"open":14401,"click":1263,"unsub":97,"complaint":12,"or":0.3421,"ctr":0.0300,"ctor":0.0877,"template_id":2317,"tags":["дайджест","активные"]}
```

Правила:

- **Ключ — `campaign_id`.** Повторный сбор статистики по той же кампании **перезаписывает** строку,
  а не добавляет новую. Цифры в RuSender дозревают неделями, и дубли сделают историю бесполезной.
- `as_of` — когда цифры сняты, `sent_at` — когда рассылка ушла. Это разные даты, и по разнице видно,
  насколько снимок свежий.
- `or` = open / delivered, `ctr` = click / delivered, `ctor` = click / open. Доли, не проценты.
  Если delivered или open равны нулю — пиши `null`, а не ноль.
- `audience.kind` — метка серии: `active`, `paid`, `reactivation`, `all`. По ней `rusender-results`
  собирает сопоставимую серию для сравнения, и от неё напрямую зависит, осмысленным получится
  сравнение или нет.

  **Метка назначается осознанно, а не выводится из имени списка.** Имена вроде «Платники Образование»
  и «Бесплатники без Gmail» на вид раскладываются автоматически, но на практике под одну метку
  съезжают письма разных типов, и серия перестаёт быть однородной. Не уверен, какую метку ставить, —
  спроси. Держись меток, уже встречающихся в файле; новую заводи, когда серия действительно другая.
- `tags` — необязательные метки для будущих разрезов.

Дописывать файл можно только целыми строками. Если строка битая — не чини угадыванием, пропусти её
и скажи человеку, в какой строке проблема.

## notes.md

Наблюдения и гипотезы по проекту. Свободная проза, но с обязательным статусом у каждой гипотезы.

```markdown
## Гипотезы

### Короткая тема с конкретной выгодой даёт более высокий OR
- Статус: открыта
- Заведена: 2026-09-18, по кампаниям 112538, 112401, 111980
- Как проверить: следующая рассылка активной аудитории с темой до 40 знаков
- Проверка: —

### Мемные картинки лучше работают в реактивации
- Статус: подтверждена 2026-08-30
- Проверка: 111204 (CTR 4,1%) против 110988 (CTR 2,6%), сопоставимая аудитория
```

Статусы: `открыта`, `подтверждена <дата>`, `опровергнута <дата>`, `отброшена <дата>` (когда стало
неактуально). Гипотезу не удаляй — опровергнутая гипотеза тоже знание.

## Совместное редактирование

Файлы могут лежать в git и правиться человеком руками. Поэтому:

- перед записью перечитывай файл, а не пиши по памяти из начала диалога;
- не переформатируй чужие строки «заодно»;
- в `PROFILE.md` меняй только те поля, о которых шла речь, и обновляй `updated`.
