# RuSender: проверка рассылки перед отправкой

**Версия:** 1.0.0 · **Лицензия:** MIT · Требует подключённого MCP-коннектора
[RuSender](https://rusender.ru/features/email/mcp/)

Проходит чек-лист по черновику рассылки и собирает карточку для подтверждения человеком: обходит все
ссылки письма и находит битые, сверяет UTM на уровне кампании и на уровне ссылок, вытаскивает
переменные из шаблона и сверяет их с полями выбранных списков, проверяет ссылку отписки и её регистр,
считает охват, показывает, не получала ли эта аудитория письмо совсем недавно, и ловит протухшее
содержимое — прошедшие дедлайны в переиспользованном черновике.

Когда настраиваешь первую рассылку за день, чек-лист проходится легко. Когда четвёртую для третьего
проекта подряд — что-нибудь пропускается. Навык проходит его одинаково на первой и на двадцатой.

**Ничего не запускает.** Отправка остаётся за человеком, двойное подтверждение живёт в
`rusender-campaign-create`.

## Установка

```bash
cp -r rusender-preflight ~/.claude/skills/      # Claude Code, личные навыки
cp -r rusender-preflight .claude/skills/        # Claude Code, навыки проекта
```

Для claude.ai запакуйте папку в ZIP и загрузите в `Settings → Capabilities → Skills`.

## Требования

- **Node 18+** для `scripts/check_links.mjs` — обхода ссылок и разбора UTM.
- Доступ к сети из среды выполнения.

В claude.ai скрипт не запустится: семь проверок из восьми работают через коннектор, а ссылки навык
честно помечает как непроверенные — вместо того чтобы написать, что всё в порядке.

## Как вызвать

Срабатывает сам после создания черновика и по запросам вида:

```
Проверь рассылку 118420 перед отправкой.
Всё ли готово к запуску?
Проверь ссылки и метки в письме.
```

Явно — `/rusender-preflight`.
