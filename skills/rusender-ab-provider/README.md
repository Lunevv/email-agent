# rusender-ab-provider-test

Skill для Claude, который создаёт и анализирует **мульти-провайдерный A/B-тест тем письма** в
[RuSender](https://rusender.ru): делит базу на сегменты по почтовым системам (Gmail, Mail.ru,
Yandex и «все остальные») и запускает для каждого сегмента отдельный A/B-тест одних и тех же
тем — одновременно. Затем сводит результаты: какая тема победила у какого провайдера.

## Зачем

Открываемость письма зависит от того, как тема выглядит у конкретного почтовика (эмодзи,
длина, прехедер) и как реагирует его аудитория. Один общий A/B-тест это усредняет. Этот скилл
показывает различия по провайдерам и помогает подбирать темы под Gmail / Mail.ru / Yandex.

## Требования

- **Подключённый MCP-коннектор RuSender** (авторизация по OAuth) с правами на кампании,
  сегменты и шаблоны. Без него скилл не сможет вызывать API RuSender.
- Площадки: **Claude Code** или **claude.ai** с подключённым RuSender MCP.
- ⚠️ Не подходит для дистрибуции через **Claude API**: там песочница без сети и без внешних
  MCP-коннекторов.

## Установка

### Claude Code
Скопируйте папку скилла в личные или проектные скиллы:
```bash
cp -r rusender-ab-provider-test ~/.claude/skills/      # personal
# или
cp -r rusender-ab-provider-test .claude/skills/        # project
```

### claude.ai
Запакуйте папку в ZIP и загрузите в **Settings → Features → Skills**.

## Использование

Скилл срабатывает автоматически, когда вы просите сравнить реакцию разных почтовых систем на
темы письма. Примеры запросов:

- «Сравни, как gmail, mail и yandex реагируют на разные темы — сделай A/B по провайдерам на
  списке "Летняя база"»
- «Запусти сплит-тест тем с разбивкой по почтовикам»

Или вызвать явно: `/rusender-ab-provider-test`.

Что скилл сделает по шагам: резолвит базу/отправителя/шаблон → создаёт 4 сегмента по
провайдерам → создаёт 4 A/B-черновика с одинаковым набором тем → подбирает тестовую долю под
размер каждого сегмента → (после подтверждения) запускает все 4 одновременно → после
завершения сводит тему-победителя и агрегатные метрики по каждому провайдеру.

## Известные ограничения

- **Нет поэлементной статистики A/B** через API RuSender — доступна тема-победитель (поле
  `subject` после завершения) и агрегат по кампании; цифры по каждому варианту темы смотреть
  в кабинете RuSender.
- **Маленькие сегменты** (< сотни на вариант) дают индикативный, а не статзначимый результат.
- **Удаление кампаний** через MCP недоступно — ошибочные черновики удаляются в кабинете.
