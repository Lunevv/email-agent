# Домены почтовых провайдеров и краевые случаи сегментации

Этот файл читается по необходимости — когда базовых условий из `SKILL.md` недостаточно
(нестандартная база, корпоративные адреса, требование полного покрытия). Для типовой задачи
он не нужен.

## Порядок и приоритет доменов

Сегменты должны быть **взаимоисключающими**, иначе один контакт попадёт в несколько A/B и
статистика поедет. Ключевая ловушка: `gmail.com` содержит подстроку `mail`, поэтому Mail.ru
нельзя ловить по `mail` — только по конкретным доменам. Сегмент «остальные» строится как
отрицание всех доменов, попавших в первые три группы, — держи списки синхронными.

## Списки доменов по группам

### Gmail
- `gmail.com`
- `googlemail.com` (старый алиас)
- Корпоративные почты на Google Workspace имеют собственный домен (`@company.com`) и по
  подстроке `gmail` НЕ ловятся — они попадут в «остальные». Это нормально: технически это
  доставка через Google, но с точки зрения бренда/темы их логичнее держать отдельно. Если
  пользователю нужно выделить именно Google Workspace — это невозможно по домену, только по
  MX-записям, которых в RuSender нет. Честно скажи об этом ограничении.

Условие: `contain "gmail"` (покрывает gmail.com и googlemail.com).

### Mail.ru group
Домены группы Mail.ru (VK):
- `mail.ru`
- `internet.ru`
- `bk.ru`
- `inbox.ru`
- `list.ru`

Условие (`applyConditionsType: or`): по одному `contain` на каждый нужный домен. Минимальный
вариант — только `mail.ru`. Полный — все пять.

### Yandex
- `yandex.ru`
- `yandex.com`
- `ya.ru`
- `yandex.by` / `yandex.kz` / `yandex.ua` (региональные, если есть в базе)

Условие (`applyConditionsType: or`): `contain "yandex"` покрывает все `yandex.*`; отдельно
добавь `contain "ya.ru"`. Региональные `yandex.*` уже покрыты подстрокой `yandex`.

### Все остальные
`applyConditionsType: and`, отрицание всех доменов выше:
`notContain "gmail"`, `notContain "mail.ru"`, `notContain "internet.ru"`, `notContain "bk.ru"`,
`notContain "inbox.ru"`, `notContain "list.ru"`, `notContain "yandex"`, `notContain "ya.ru"`.

Сюда попадут: корпоративные домены, Outlook/Hotmail, Rambler, Proton, зарубежные ящики и т.п.
При желании их можно вынести в отдельные группы тем же приёмом (по одному сегменту на
провайдера + campaign.listIds для привязки к базе).

## Проверка покрытия и непересечения

После создания всех сегментов и до запуска:
1. По каждой кампании вызови `ab_test_preview` и запиши `totalContacts`.
2. Сумма `totalContacts` по 4 сегментам должна ≈ равняться размеру базы
   (`lists_get_by_id.contactsCount` за вычетом невалидных статусов).
3. Если сумма БОЛЬШЕ базы — сегменты пересекаются (ищи домен, попавший в два условия).
   Если МЕНЬШЕ — часть контактов не попала никуда (ожидаемо, если «остальные» не заводили,
   либо есть адреса с доменами из «серой зоны»). Сообщи пользователю расхождение числом.

## Частые вопросы
- **«Хочу только mail.ru, без bk/inbox/list»** — оставь в Mail.ru-сегменте одно условие
  `contain "mail.ru"`, а в «остальных» убери отрицания bk/inbox/list (иначе эти домены не
  попадут никуда). Списки в двух местах всегда держи согласованными.
- **«Добавь Outlook отдельной группой»** — новый сегмент `or`: `contain "outlook"`,
  `contain "hotmail"`, `contain "live."`; и добавь их отрицания в «остальные».
