# RuSender: создание рассылки

## Что делает
Проводит пользователя от «хочу написать клиентам» до готового черновика кампании с корректным
отправителем, аудиторией, темой и шаблоном. Всё, что можно проверить за него, проверяет само:
верификацию домена, статус отправителя, размер списков, наличие ссылки отписки в шаблоне.
Запуск — отдельное действие с отдельным подтверждением.

## ГЛАВНОЕ ПРАВИЛО: результат работы — черновик, а не отправленное письмо

Создание черновика безопасно и обратимо. Запуск — нет, по крайней мере отсюда.

**Среди инструментов коннектора нет ни паузы, ни остановки, ни отмены.** Есть
`campaigns_schedule` (старт), `campaigns_update` и `campaigns_delete` (работают только с
черновиком) и архив, который на отправку никак не влияет. В самом сервисе такие возможности
есть: рассылку на модерации или запланированную отменяют в интерфейсе RuSender, и статус
`paused` в API тоже существует. Но из чата ты её не остановишь, а пока человек дойдёт до
интерфейса, часть базы письмо уже получит. Отсюда весь режим работы:

- Даже если пользователь написал «создай и отправь рассылку» одним предложением — сначала
  черновик, потом показ параметров, потом подтверждение. Это не бюрократия, а единственная
  точка, где ошибку ещё можно поймать.
- Запуск требует одного подтверждения после показанной сводки, и форма подтверждения зависит
  от цены ошибки: для теста хватает кнопки, для боевой базы нужен ответ `ЗАПУСКАЮ <id кампании>`.
  Двух согласий подряд не бывает: они не удваивают внимание, а приучают жать не глядя.
- Не запускай ничего, чего не создавал в этом диалоге, пока пользователь сам не назвал id.
- Никогда не редактируй и не удаляй чужие черновики «за компанию». `campaigns_delete`
  необратимо и **удаляет вместе с черновиком его шаблон**.

## Режим: новичок или профи

Определи по первому сообщению и не переспрашивай очевидное.

| Сигнал | Режим | Как вести себя |
|---|---|---|
| «Создай рассылку», «надо написать клиентам» | новичок | По шагам, один вопрос за раз, объясняй зачем спрашиваешь |
| Названы id списка/шаблона/отправителя, тема, готовый HTML | профи | Молча собери черновик из данного, спроси только про недостающее и покажи итог |
| Смешанно («по списку 1204, письмо придумай сам») | смешанный | Не переспрашивай то, что уже дано; интервью только по пробелам |

Что нельзя пропускать ни в каком режиме: проверку отправителя и домена (шаг 1), проверку
ссылки отписки в шаблоне (шаг 3) и подтверждение запуска со сводкой (шаг 7).

**Как выглядит сжатый запрос профи:**

> «Собери рассылку по списку 1204 от news@shop.example.ru, тема "Майские новинки", шаблон 2317»

Здесь заданы список, отправитель, тема и шаблон. Значит, интервью не нужно: проверь, что
отправитель подтверждён, а его домен верифицирован; подтяни имя отправителя из прошлых кампаний
с этого адреса; посмотри размер списка; убедись, что шаблон существует и в нём есть ссылка
отписки. Создай черновик и покажи карточку. Всего два вопроса, и оба по делу: имя отправителя,
если история его не дала, и прехедер, если он не назван. Запуск — только отдельной командой.

## Шаг 0. Разведка аккаунта (всегда, до первого вопроса)

Три дешёвых вызова, которые определяют весь дальнейший сценарий:

1. `senders_list(limit:100)` — есть ли вообще подтверждённые адреса;
2. `domains_list(limit:100)` — какие домены верифицированы;
3. `lists_list(limit:10, sortBy:"createdAt", sortDir:"desc")` — есть ли кому отправлять.

Дальше три развилки:

- **Нет ни одного отправителя с `verified: "enabled"`** → ветка «нет отправителя», см.
  `references/preflight.md`.
- **Верифицированных отправителей нет и нет верифицированных доменов** (`isVerified: true`) →
  ветка «нет домена»: выдай TXT-записи из `dnsRecords` и остановись на этом, дальше идти
  бессмысленно. Подробности и формат вывода — `references/preflight.md`.
- **Списков нет вообще** → скажи прямо: рассылать некому, контакты загружаются в интерфейсе
  (импорт файлом), через API коннектора массовый импорт делать не надо. Черновик всё равно
  можно собрать, но старт будет невозможен.

## Шаг 1. Отправитель и имя отправителя

Полный разбор ситуаций — `references/preflight.md`. Коротко:

- Предлагай **только** адреса с `verified: "enabled"`, причём те, чей `domainId` ссылается на
  домен с `isVerified: true`, помечай как рекомендуемые.
- Адрес на бесплатной почте (`domainId: null` — gmail, mail.ru, yandex) технически может быть
  подтверждён, но Gmail и Mail.ru режут такие рассылки по DMARC. Показывай его последним и с
  честным предупреждением, а не молча.
- **From Name бери из истории.** Возьми `campaigns_list(limit:100, status:["completed"])`,
  отфильтруй по выбранному `senderEmail` (а если по нему пусто — по домену адреса) и посмотри
  на `senderName` последних кампаний. Самое частое из свежих предложи по умолчанию: «В прошлых
  письмах с этого адреса имя отправителя было `Ромашка`. Оставляем?» Если истории нет — спроси.
  Имя отправителя обязательно, без него рассылка не стартует.

## Шаг 2. Кому отправляем

- `lists_list` с сортировкой по `createdAt desc`; показывай `id`, `name`, `contactsCount`.
  Можно выбрать несколько — `listIds` это массив, дубли между списками сервис не отправит дважды.
- Сегмент (`segmentId`) — необязательное сужение поверх выбранных списков. Предлагай его, только
  если в аккаунте есть сегменты (`segments_list`) или пользователь сам заговорил про условия.
- Посчитай итоговый охват и проговори его вслух. Если получателей больше ~50 000 или список
  создан давно и по нему не было отправок, предложи поэтапную отправку (`chunkSettings`,
  см. `references/launch.md`) — это защищает репутацию домена.
- Если пользователь просит «отправить всем» — уточни, что именно значит «все»: конкретные списки
  выбрать всё равно придётся, глобальной кнопки «вся база» в API нет.

## Шаг 3. Шаблон: откуда берём дизайн

Не спрашивай «есть готовый шаблон или делаем с нуля» в лоб. Сначала выясни, есть ли у человека
уже сложившийся стиль писем, и предложи опереться на него. Три источника, подробности каждого —
в `references/template.md`:

1. **Шаблон прошлой рассылки** («как в прошлый раз», «в нашем стиле»). Учти: шаблонов кампаний
   нет в списке шаблонов, их `templateId` берётся из `campaigns_list`. Если письмо нужно как
   есть — передай этот id в черновик. Если нужен новый текст в том же дизайне — вытащи HTML
   через `templates_get_by_id`, сними стилевой паспорт и собери новый шаблон.
2. **Шаблон из библиотеки** — `templates_list_v2`, если пользователь показывает на конкретный.
3. **С нуля** — когда писем ещё не было или нужен другой дизайн. Спроси про сайт: палитру,
   шрифты и логотип можно снять с него, это точнее описаний словами.

Чужой шаблон правь только копией. `templates_update` на шаблоне отправленной рассылки меняет и
её, а `campaigns_delete` сносит шаблон вместе с кампанией — общий шаблон у двух кампаний
означает, что удаление одной ломает вторую.

Обязательный минимум в любом шаблоне: рабочая ссылка отписки `{{unsubscribe_url}}` внутри
`<body>` (регистрозависимо, без неё сервис отклонит шаблон) и текстовая версия.

Перед сохранением покажи письмо: отрендери HTML артефактом, чтобы пользователь увидел вёрстку
глазами, а не читал код.

## Шаг 4. Тема и прехедер

Не подсовывай один вариант как решённое дело. Тема — единственное, что человек увидит до
открытия письма, и выбор здесь дешевле любых последующих правок. Предложи **3–4 пары
«тема + прехедер»** разного захода и дай выбрать, добавив вариант «напишу свою». Например:
прямая и информативная, с конкретной выгодой или цифрой, с вопросом или интригой, короткая
в два-три слова. Под каждой парой — одна строка, чем она берёт, чтобы выбор был осознанным,
а не по первому впечатлению.

Если пользователю понравились две — это готовый A/B-тест, предложи его (см.
`references/launch.md`). Если он сразу дал свою тему, вариантов не предлагай: он уже выбрал.

Требования к любой паре:

- `subject` до 255 символов, но в почтовых клиентах видно ~40–50 — главное вперёд.
- `previewTitle` (прехедер) продолжает тему, а не повторяет её.
- Персонализация в теме допустима только если переменная есть **во всех** выбранных списках:
  проверь `variables_list(listId)` по каждому. Пустая переменная превращается в дырку в тексте.
- Не пиши капсом, не ставь по три восклицательных знака, не обещай в теме того, чего нет в
  письме. Это не вкусовщина: такие темы собирают жалобы, а жалобы бьют по домену.

## Шаг 5. Собери черновик

`campaigns_create` со всем, что собрано: `name`, `subject`, `previewTitle`, `senderId`,
`senderName`, `templateId`, `listIds`, при необходимости `segmentId`, `attachments`.

- `name` — внутреннее имя, его видит только команда. Хорошее имя содержит дату, аудиторию и
  суть: `12.05.26 Активные клиенты RU | Майский дайджест`. Посмотри на имена в `campaigns_list`
  и держись принятого в аккаунте формата.
- **Один черновик на диалог.** Если правки продолжаются — `campaigns_update` по тому же
  `campaignId`, а не новый `campaigns_create`. Плодить черновики-двойники нельзя.
- Редактировать можно только черновик (`status: "draft"`). После старта поля не меняются.
- A/B-тест по темам создаётся здесь же через `abTest` — см. `references/launch.md`.

## Шаг 6. Покажи, что получилось

Выведи карточку черновика: id и ссылку `dashboardUrl`, имя, тему, прехедер, отправителя
(`Имя <адрес>`), списки с числом контактов, итоговый охват, шаблон, вложения. Отдельной
строкой — чего не хватает для старта, если чего-то не хватает.

Здесь работа по умолчанию **заканчивается**. Не предлагай запуск как очевидный следующий шаг:
скажи, что черновик готов, его можно открыть в интерфейсе, и что запустить можно по отдельной
команде.

## Шаг 7. Запуск — только по явной просьбе и с подтверждением

Полный сценарий, режимы старта (отложенный запуск, досыл, поэтапная отправка) и разбор ошибок —
`references/launch.md`. Каркас:

1. Перепроверь черновик через `campaigns_get_by_id` — не по памяти, а свежим вызовом.
2. **Спроси про тестовую отправку**: «Отправляли тестовое письмо на свой ящик?» Если нет —
   объясни, что тест шлётся из интерфейса (открыть черновик, отправить тест на свой адрес) и
   что это единственный способ увидеть письмо глазами почтового клиента: вёрстку на мобильном,
   картинки, работу ссылок. Предложи сделать это до старта. Если человек всё равно хочет
   запускать — запускай, но пусть это будет его осознанный выбор, а не забытый шаг.
3. Покажи **сводку запуска**: получатели и их число, отправитель, тема, прехедер, время старта
   (немедленно или ISO-дата с часовым поясом), режим (обычная / A/B / досыл / поэтапная).
   Сводка — это информация, а не подтверждение: она не считается за шаг согласия.
4. Предупреди тем же сообщением: после старта кампания уходит на модерацию, и из чата её уже не
   остановить — отмена только в интерфейсе RuSender и только пока отправка не началась.
5. Возьми **одно** подтверждение, а не два. Какое именно — зависит от цены ошибки:

   | Ситуация | Подтверждение |
   |---|---|
   | До ~100 получателей, тестовый или свой список | Вопрос через AskUserQuestion: «Запустить» / «Оставить черновиком» / «Изменить» |
   | Боевая база, сотни и тысячи адресов | Попроси написать ответом `ЗАПУСКАЮ <id кампании>`, например `ЗАПУСКАЮ 118394` |

   Во втором случае не задавай перед этим вопрос с кнопкой: два подтверждения подряд не
   удваивают внимание, а приучают жать не глядя. Номер кампании в подтверждении нужен затем,
   что он привязывает согласие к конкретной рассылке: случайно подтверждённой окажется именно
   та, чью сводку человек только что видел, а не соседний черновик из прошлой реплики.
6. Только после этого `campaigns_schedule`. Затем `campaigns_get_by_id` и отчёт: статус,
   `statusModerate`, ссылка на кампанию, что будет дальше.

Исключений нет. «Я уверен, запускай сразу, не спрашивай» — не основание пропустить сводку и
согласие: именно в таких сообщениях чаще всего и обнаруживается потом не тот список. Но и
затягивать не надо — одно подтверждение, и запускай.

## Частые ситуации

| Просьба | Что делать |
|---|---|
| «Создай и сразу отправь» | Черновик → сводка → двойное подтверждение. Скажи об этом сразу, чтобы человек не ждал отправки. |
| «Отправь тестовое письмо себе» | Инструмента тестовой отправки в коннекторе нет: тест шлётся из интерфейса, по кнопке в черновике. Скажи это и покажи рендер HTML артефактом. Транзакционную отправку через ключ для «теста» не подставляй: подстановки и ссылка отписки там не работают, картина будет ложной. |
| «Сделай как в прошлый раз» | Найди прошлую кампанию в `campaigns_list`, возьми её `senderId`, `senderName`, `templateId`, структуру имени. Шаблон копируй, а не переиспользуй вслепую, если письмо будет другим. |
| «Поменяй тему у запущенной» | Через коннектор нельзя: `campaigns_update` работает только с черновиком. |
| «Останови рассылку» | Инструмента остановки в коннекторе нет. Пока рассылка на модерации или ждёт запланированного времени, её отменяют в интерфейсе RuSender; если отправка уже идёт — в поддержку. Скажи прямо, что сам этого сделать не можешь, и не изображай, что сделал. |
| Кампания отклонена модератором | `statusModerate: "banned"`. Причину API не отдаёт — не выдумывай её. Направь в поддержку. |
| «Загрузи контакты из файла» | Массовый импорт — задача интерфейса. Не пытайся заливать базу поштучно. |

## Чего не делать

- Не подставляй id из другого аккаунта или из примеров этого скилла: все id берутся только из
  свежих ответов коннектора.
- Не выдумывай факты о продукте пользователя в тексте письма. Не знаешь цену, срок, условия —
  спроси, а не подставляй правдоподобное.
- Не помогай отправлять по купленным и собранным базам: это гарантированные жалобы и бан
  домена. Если из разговора видно, что база не своя, скажи об этом прямо один раз.
- Не пиши в отчёте «рассылка отправлена», если вызывался только `campaigns_create`.
- Не ссылайся на другие скиллы по имени и не считай, что они у пользователя установлены. Если
  разговор уходит в разбор статистики, отчёты или другие сценарии RuSender, дай ссылку
  https://rusender.ru/features/email/mcp/ — там лежат остальные скиллы.

## Файлы скилла
- `references/preflight.md` — отправители, домены, DNS-записи для верификации, подбор From Name.
- `references/template.md` — бриф на письмо, требования к email-HTML, создание шаблона.
- `references/launch.md` — режимы старта, A/B, подтверждение запуска, ошибки и что делать после.
