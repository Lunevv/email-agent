# Агент email-маркетолога для RuSender

Три навыка, которые вместе превращают набор инструментов RuSender в агента, ведущего рассылки по
нескольким проектам: с памятью о каждом продукте, с чек-листом перед отправкой и с оценкой
результата на фоне собственной истории проекта.

Дополняют существующие навыки из [`Rusender/rusender-mcp`](https://github.com/Rusender/rusender-mcp),
не заменяя их.

## Что это закрывает

| | |
|---|---|
| **rusender-agent** | Помнит контекст 12 проектов. Опознаёт по задаче, о каком речь, поднимает профиль и разворачивает в параметры кампании |
| **rusender-preflight** | Девять проверок перед отправкой: ссылки, UTM, переменные против полей базы, отписка, охват, пересечения с недавними рассылками, протухшие дедлайны |
| **rusender-results** | Забирает статистику, пишет в историю проекта, сравнивает с сопоставимой серией, разделяет факт, наблюдение и гипотезу |

Работа делится так: `rusender-agent` опознаёт проект → `rusender-campaign-create` собирает черновик →
`rusender-preflight` проверяет → **человек подтверждает запуск** → `rusender-results` разбирает итог.

## Кнопка Send остаётся у человека

Ни один из трёх навыков не вызывает `campaigns_schedule`. Запуск живёт в `rusender-campaign-create` с
двойным подтверждением, и обойти его отсюда нельзя.

Причина простая: у автоматизации должна быть цена ошибки. Спорная гипотеза в отчёте — неприятно.
Неправильное письмо на пятьдесят тысяч человек — совсем другой уровень, и остановить его из чата
невозможно: инструментов паузы и отмены в коннекторе нет.

Поэтому чтение, анализ, проверки, сборка черновика и отчётность работают почти автономно, а там, где
действие не отменить, остаётся подтверждение человеком.

## Установка

```bash
cp -r skills/rusender-agent skills/rusender-preflight skills/rusender-results ~/.claude/skills/
```

Для claude.ai — запаковать каждую папку в ZIP и загрузить в `Settings → Capabilities → Skills`.

Нужен подключённый MCP-коннектор RuSender: `https://mcp.rusender.ru/mcp`, авторизация через OAuth.
Инструкция — [rusender.ru/features/email/mcp](https://rusender.ru/features/email/mcp/).

Рядом стоит поставить `rusender-campaign-create` из основного репозитория: без него агент опознает
проект и подготовит параметры, но черновик собирать будет нечем.

## Требования

| | |
|---|---|
| Клиент | Claude Code — полностью. claude.ai — без памяти между диалогами и без проверки ссылок |
| Node | 18+ для `check_links.mjs` |
| Сеть | Нужна для обхода ссылок письма |
| Claude API | Не поддерживается: песочница без сети и без внешних коннекторов |

## Память

Файлы в `.rusender-agent/` в рабочей папке:

```
.rusender-agent/
  ACCOUNT.md                     # домены, отправители, дата сверки
  projects/<slug>/PROFILE.md     # продукт, аудитория, тон, отправитель, запреты, частота
  projects/<slug>/history.jsonl  # по строке на кампанию, ключ — campaign_id
  projects/<slug>/notes.md       # гипотезы со статусом
```

Обычные текстовые файлы: читаются глазами, правятся руками, версионируются в git.

**Персональных данных подписчиков в них нет и быть не должно** — только агрегаты уровня кампании.
Файлы попадают в git и в бэкапы, и это ограничение не смягчается.

## Попробовать без своего аккаунта

В комплекте три вымышленных профиля — магазин, SaaS и онлайн-школа
(`skills/rusender-agent/references/example-projects/`). На них работает всё, что не требует живого
аккаунта: опознание проекта, тон письма, разбор UTM, логика проверок.

У магазина есть и демо-история из пятнадцати кампаний, поэтому на нём видно две вещи, которые иначе
показать нечем: предупреждение о слишком частой отправке одной аудитории и сравнение результата с
сопоставимой серией. У двух других истории нет — и на них видно, как навык честно говорит, что
сравнивать не с чем.

```
Покажи, как работает агент, на демо-проектах.
```

## Чего эти навыки не делают

Честный список, чтобы не искать кнопку, которой нет:

- **Не останавливают запущенную рассылку.** Ни паузы, ни отмены в коннекторе нет. Отменить можно
  только в интерфейсе RuSender и только пока отправка не началась.
- **Не считают конверсии и выручку.** В RuSender их нет — есть клик по ссылке. Называть клик
  конверсией нельзя, это внешняя аналитика.
- **Не знают целевых действий пользователя.** «Открывал, но не покупал» посчитать нельзя. «Открывал,
  но не кликал» — можно.
- **Не просыпаются сами.** Чтобы вернуться за дозревшей статистикой, нужен планировщик или просьба
  человека.
- **Не считают частоту по каждому контакту.** Пересечения аудиторий решаются сегментом-исключением;
  поимённый подсчёт постраничный и на десятках тысяч контактов стоит сотни вызовов.
