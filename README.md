# Агент email-маркетолога

Агент, который ведёт рассылки по нескольким проектам сразу: помнит контекст каждого продукта,
собирает письма, проверяет их перед отправкой и разбирает результат на фоне собственной истории
проекта.

Работает через MCP-коннектор сервиса рассылок. По умолчанию — [RuSender](https://rusender.ru/);
под другой сервис подключение переделывается, см. [Другой ESP](#другой-esp).

**Кнопку Send агент себе не забирает.** Всё остальное — да.

> Агент вырос из рабочей задачи: двенадцать проектов и один человек, который настраивал по ним
> рассылки. История о том, как это получилось и что из этого вышло, — в статье «Агент, который
> меня заменил». Ссылка появится здесь, когда статья выйдет.

---

## Что внутри

Тринадцать навыков. Три написаны для этого агента, десять взяты готовыми из
[Rusender/rusender-mcp](https://github.com/Rusender/rusender-mcp) — и **все тринадцать вам доступны**,
их не надо ставить по отдельности или искать где-то ещё.

### Память и проекты

| Навык | Что делает |
|---|---|
| **rusender-agent** | Хаб. Помнит контекст проектов, опознаёт по задаче, о каком речь, зовёт нужный навык и подсказывает следующий шаг. Плюс обзор по всем проектам сразу: где выбран лимит, где просел OR, где залежался черновик |
| **rusender-preflight** | Девять проверок черновика: ссылки, UTM, переменные против полей базы, отписка, охват, пересечения аудиторий, протухшие дедлайны. Собирает карточку для подтверждения |
| **rusender-results** | Метрики отправленной рассылки, запись в историю проекта, сравнение с сопоставимой серией, разделение факта, наблюдения и гипотезы |

### Рассылки

| Навык | Что делает |
|---|---|
| **rusender-campaign-create** | Собирает рассылку по шагам и сохраняет черновиком. Запуск — только после отдельного подтверждения |
| **rusender-ab-provider** | Мульти-провайдерный A/B-тест: делит базу на Gmail / Mail.ru / Yandex / остальных и тестирует темы в каждом |
| **rusender-japanese-style** | HTML-шаблон делового письма в японском стиле с сезонной палитрой и реальной погодой в городе получателя |

### Отчёты

| Навык | Что делает |
|---|---|
| **rusender-account-report** | Дашборд по аккаунту: база, объёмы, инфраструктура, проблемы конфигурации |
| **rusender-campaign-report** | Дашборд по одной рассылке: воронка, динамика открытий, клики, доставляемость |
| **rusender-ab-report** | Дашборд по A/B-тесту: варианты тем, победитель, матрица «тема × провайдер» |
| **rusender-campaign-timeline** | Таймлайн отправок: что и когда уходило, где были паузы |
| **rusender-key-dashboard** | Дашборд по транзакционному ключу: письма, OR, CTR, ошибки, темы |

### Обслуживание и прочее

| Навык | Что делает |
|---|---|
| **rusender-campaign-cleanup** | Архивирует заблокированные и отклонённые модератором рассылки |
| **rusender-send-date-oracle** | Шуточный оракул даты отправки: нумерология и фаза Луны. Это развлечение, а не аналитика |

Звать по именам не нужно — достаточно сказать словами, что надо. Агент сам выберет навык и
подскажет, чем продолжить.

## Установка

```bash
git clone https://github.com/Lunevv/email-agent.git
cd email-agent
./scripts/install.sh --copy
```

Это положит все тринадцать навыков в `~/.claude/skills/` — они станут доступны во всех сессиях
Claude Code, не только в этой папке.

Для разработки есть режим симлинков (`./scripts/install.sh` без аргументов): правки в репозитории
видны сразу, без переустановки. А `--project` ставит навыки только в текущую папку,
в `.claude/skills/`, если не хотите трогать общие.

**Работать удобнее прямо из склонированной папки** — в ней лежат демо-проекты, и агент их найдёт.
Убрать установленное: `./scripts/install.sh --remove`.

Для claude.ai — запакуйте нужную папку из `skills/` в ZIP и загрузите в
`Settings → Capabilities → Skills`.

### Подключение RuSender

**1. Завести аккаунт**, если его нет: https://app.rusender.ru/auth/register/

**2. Добавить MCP-сервер** в ИИ-клиент. Адрес один и тот же везде:

```
https://mcp.rusender.ru/mcp
```

В Claude Code — из терминала:

```bash
claude mcp add --transport http rusender https://mcp.rusender.ru/mcp
```

В Claude Desktop и на claude.ai — в настройках коннекторов, «добавить пользовательский коннектор».
Готовые конфиги для Cursor и VS Code лежат в
[clients/](https://github.com/Rusender/rusender-mcp/tree/master/clients).

**3. Авторизоваться через OAuth.** Откроется окно браузера, вход в аккаунт RuSender. Ключи и токены
копировать никуда не нужно — если у вас их просят, что-то пошло не так.

**4. Проверить, что подключилось.** В новой сессии спросите:

```
Покажи моих отправителей в RuSender
```

Если пришёл список адресов — всё работает. Если агент говорит, что коннектора нет, — вернитесь к
шагу 2.

Подключение бесплатное. На бесплатном тарифе — до 100 отправок по API и рассылки по базе до
500 контактов, этого хватает, чтобы всё попробовать.

### Первый запуск

```
Заведи проекты по моему аккаунту.
```

Агент посмотрит отправителей, домены, списки и кампании, предложит разбивку на проекты и
доспросит то, чего в API нет: тон, запреты, частоту. Дальше можно работать словами:

```
Подготовь рассылку для uKit, вот текст. Возьми наш стандартный шаблон.
Проверь черновик 118902.
Как отработало последнее письмо? Сравни с прошлыми.
Сделай обзор аккаунта.
```

## Попробовать без своего аккаунта

В `projects/` лежат двенадцать демо-проектов — интернет-магазин, SaaS, онлайн-школа, клиника,
фитнес, медиа, B2B-логистика, мобильная игра, travel, доставка еды, бухгалтерия и анонимизированный
реальный проект.

У каждого: профиль с тоном и запретами, история рассылок, метаданные списков, текст письма, готовый
HTML-шаблон и лог действий. Всего 880 кампаний, 13 писем и 13 шаблонов.

Отдельно закрыты нетипичные случаи:

- **Двуязычный проект** (`saas-taskly`) — RU и EN уходят парой в один день, но считаются разными
  сериями: EN-платники стабильно открывают ниже RU, и сравнивать языки между собой нельзя.
- **Транзакционные письма** (`food-bystro`) — три ключа отправки, коды и статусы заказов. На них
  работает `rusender-key-dashboard`.
- **Ежедневный дайджест** (`media-kontur`) — 7 писем в неделю это норма проекта, и частотный лимит
  не должен на неё ругаться.
- **Маленькая база** (`logist-tochka`) — 5 тысяч контактов, где выводы по одной рассылке делать
  нельзя.

```
Покажи, какие есть проекты.
Подготовь рассылку для Розы.
Разбери транзакционный ключ доставки еды.
Проверь черновик подборки для Маршрута.
```

Последняя команда — на заранее заготовленном черновике
(`projects/travel-marshrut/letters/DRAFT-podborka-noyabr.md`), в который специально заложены три
ошибки: подстановка, которой нет в базе, прошедший дедлайн и ссылка на несуществующий домен.
Удобно, чтобы посмотреть, как выглядит остановка отправки.

Демо-проекты помечены `demo: true` — агент не подставит их id в реальный коннектор.

Шаблоны сделаны из стандартной библиотеки RuSender: вёрстка настоящая, с поддержкой Outlook.
Картинки указывают на CDN RuSender — **перед реальной отправкой их надо заменить на свои**, об этом
написано в шапке каждого файла.

## Память агента

Всё, что агент знает о проектах, лежит обычными файлами:

```
projects/<slug>/
  PROFILE.md       продукт, аудитория, тон, отправитель, запреты, частота
  lists.md         метаданные списков и сегментов
  history.jsonl    по строке на кампанию: метрики
  notes.md         гипотезы со статусом
  log.md           что агент делал и чем кончилось
  letters/         тексты отправленных писем
  templates/       HTML-шаблоны
  reports/         собранные отчёты
```

Читаются глазами, правятся руками, версионируются как обычный код.

**Персональных данных подписчиков там нет и быть не должно** — только метаданные и агрегаты. Папки
попадают в бэкапы и репозитории, и так утекают клиентские базы. Контакты живут в сервисе рассылок,
агент берёт их оттуда в момент работы.

Боевые проекты кладутся в `projects.live/` — эта папка в `.gitignore` и не попадает в релиз. Есть
она — агент работает в ней, нет — в `projects/`.

## Другой ESP

Агент сделан на RuSender, но не привязан к нему намертво. Скажите, каким сервисом пользуетесь, и
агент разберёт, что получится, а что нет.

Переносится: проверка ссылок и UTM, структура памяти и папок, девять проверок как сценарий,
разделение факта и гипотезы, правило про кнопку Send.

Привязано к RuSender: имена инструментов, исключение аудитории по «не получал кампанию X», подсчёт
охвата, отчётные навыки целиком.

Полный список из пятнадцати возможностей с местом под ваш сервис — в
[docs/connector-contract.md](docs/connector-contract.md).

## Автообновление статистики

Агент не просыпается сам. В комплекте лежит готовая задача для планировщика —
[`routines/daily-refresh.md`](routines/daily-refresh.md): будние дни, 10:00, обновляет метрики
кампаний за последние две недели и отмечает, где цифры разошлись с серией.

**По умолчанию выключена.** Как включить — [docs/scheduling.md](docs/scheduling.md).

В расписание не ставится ничего, что отправляет письма.

## Разработка

```bash
./scripts/install.sh        # симлинки: правки видны сразу
./scripts/smoke.sh          # проверить, что ничего не развалилось
./scripts/lint.py           # структура навыков и контрактов
./scripts/sync-skills.sh    # что изменилось в upstream

# пересборка демо-данных, в таком порядке:
node scripts/make-demo.mjs
node scripts/anonymize.mjs projects.live/rusender projects/rusender
node scripts/add-conversions.mjs
node scripts/make-transactional.mjs
node scripts/link-letters.mjs
node scripts/make-notes.mjs
python3 scripts/make_templates.py ~/Downloads/template.xlsx
```

Навыки из upstream скопированы в `skills/` и зафиксированы в `SKILLS.lock` с номером коммита.
`sync-skills.sh --apply` обновляет копии и переписывает lock.

## Чего агент не делает

- **Не останавливает запущенную рассылку.** Ни паузы, ни отмены в коннекторе нет.
- **Не добывает конверсии и выручку.** В сервисе рассылок их нет — есть клик по ссылке. Если поля
  `conversions` и `revenue` заполнены в истории, агент их покажет и сравнит с серией, но запросить
  неоткуда: коннектора к BI у него нет. Нет полей — так и скажет, а не выведет продажи из кликов.
- **Не знает целевых действий пользователя.** «Открывал, но не покупал» посчитать нельзя,
  «открывал, но не кликал» — можно.
- **Не просыпается сам.** Чтобы вернуться за дозревшей статистикой, нужен планировщик или просьба.
- **Не хранит контакты.** Только метаданные списков.
