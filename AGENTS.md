# Запуск в других ИИ

Агент собран для Claude Code, но не завязан на него. Навыки — обычные Markdown-файлы, а не код:
любой ассистент, который умеет читать файлы и звать MCP-инструменты, может ими пользоваться.

Этот файл — для ассистента, который открыл репозиторий не в Claude Code.

## С чего начать

1. Прочитай `skills/rusender-agent/SKILL.md` — это хаб: он описывает, как опознать проект, где
   лежит память и какой навык звать под какую задачу.
2. Дальше открывай тот навык, который нужен задаче. Список — в
   `skills/rusender-agent/references/skills-roster.md`.
3. Память проектов — в `projects/` (демо) или `projects.live/` (боевые данные, если папка есть).
   Формат описан в `skills/rusender-agent/references/data-layout.md`.

Файлы навыков называют MCP-инструменты без префикса: `public_campaigns_list`,
`public_senders_list` и так далее. Префикс подставляет клиент — в одних он выглядит как
`mcp__rusender__public_campaigns_list`, в других иначе. Не хардкодь его, ищи инструмент по имени.

## Что устроено по-разному в разных клиентах

| | Claude Code | claude.ai | Codex, Cursor, прочие |
|---|---|---|---|
| Файлы памяти | да | нет | обычно да |
| Запуск скриптов | да | нет | зависит от клиента |
| Проверка ссылок | полностью | без сети | если есть Node и сеть |
| Вызов навыка по имени | `/rusender-agent` | по названию | просто открой SKILL.md |

Нет доступа к файлам — агент всё равно полезен: опознание проекта, разворачивание параметров,
проверки через коннектор работают. Не работает только память между диалогами. Скажи об этом один
раз и не возвращайся к теме.

Нет возможности запускать скрипты — `skills/rusender-preflight/scripts/check_links.mjs` не
отработает. Разбери ссылки и UTM-метки по HTML шаблона сам, а в карточке напиши, что доступность
ссылок не проверена. **Не пиши, что ссылки в порядке.**

Есть Node, но нет сети — запусти скрипт с флагом `--no-network`: он разберёт метки и найдёт
относительные ссылки, не ходя наружу.

## Чего не делать ни в каком клиенте

- **Не запускать рассылку без явного подтверждения человеком.** Отправку начинает
  `public_campaigns_schedule`. У RuSender нет ни паузы, ни отмены: остановить рассылку из чата
  невозможно. Это правило не смягчается формулировкой задачи вроде «создай и сразу отправь».
- **Не записывать в файлы персональные данные подписчиков.** Ни адресов, ни имён, ни поимённых
  списков открывших. Папки проектов попадают в репозитории и бэкапы. Подробности и список
  параметров, которые надо вычищать из URL, — в `data-layout.md`.
- **Не подставлять id из демо-профилей** (у них `demo: true`) в настоящий коннектор.
- **Не просить у человека API-ключи.** Авторизация в RuSender идёт через OAuth.

## Другой сервис рассылок

Отчётные навыки написаны под RuSender API и на другой сервис не переносятся. Три навыка агента —
`rusender-agent`, `rusender-preflight`, `rusender-results` — переносятся, если у сервиса есть MCP.

Что именно им нужно от сервиса, с местом под ваш адаптер, — в `docs/connector-contract.md`.

## Структура репозитория

```
skills/           13 навыков, каждый самодостаточен
projects/         12 демо-проектов: профили, история, письма, шаблоны, логи
projects.live/    боевые данные, если заведены. В git не попадает
docs/             контракт коннектора
scripts/          установка, синхронизация с upstream, генерация демо, проверки
SKILLS.lock       какие навыки взяты из upstream и на каком коммите
```
